# Курица — Эксперт

Учёт оптового импортёра замороженной курицы и утки (Кыргызстан): партии из Китая и РФ, склад,
взаиморасчёты с контрагентами, займы, квоты, касса, плановые расходы (налоги) и аналитика.
Данные хранятся в базе **Tablox** (платформа на основе Teable), приложение — Next.js на Vercel.

Все итоговые цифры повторяют формулы исходного Excel-файла клиента; у каждой вычисляемой
цифры в интерфейсе есть подсказка ⓘ «как считается» со ссылкой на ячейку Excel.

Кнопка «Зафиксировать баланс» на сводке сохраняет цифры «баланса денег» на дату в таблицу «Снимки баланса»
(исходный Excel клиента лежит там же первым снимком). В журнале склада у каждой отгрузки есть наценка к
себестоимости: по партии отгрузки, а если партия не указана — по средней себестоимости партий товара (≈).

## Запуск

```bash
npm install
cp .env.example .env.local   # заполнить TEABLE_APP_TOKEN
npm run dev
```

| Переменная | Назначение |
|---|---|
| `TEABLE_API_URL` | адрес Tablox, `https://tablo-x.com` |
| `TEABLE_APP_TOKEN` | персональный токен Tablox с доступом только к базе проекта (секрет) |
| `TEABLE_BASE_ID` | ID базы |
| `APP_PASSWORD` | пароль входа в приложение (HTTP Basic Auth, логин любой); пусто — без пароля |

Токен используется только на сервере (`app/actions.ts`, `lib/`), в браузер не попадает.

## Устройство

- `app/actions.ts` — серверные действия: чтение таблиц через REST API Tablox, сохранение с проверками
  (остаток склада, остаток квоты/лицензии, переплата налога), приёмка партии, отгрузка, оплата налога.
- `app/workspace.tsx` — оболочка и основные разделы; отдельные разделы: `warehouse-view`, `batches-list`,
  `loans-view`, `quotas-view`, `suppliers-view`, `analytics-view`, `summary-view`, `snapshots-view`, `finance-views`.
- `app/finance.ts` — расчёт сводки («баланс денег» из Excel), `app/record-info.ts`, `app/batch-calculations.tsx` —
  тексты подсказок «как считается».
- `schema/*.json` — схема таблиц базы; обновляется командой `node scripts/sync-schema.mjs`.
- `proxy.ts` — вход по паролю.

## Скрипты проверки

```bash
npx tsx scripts/e2e-check.mts          # сквозной сценарий на реальной базе: создаёт тестовые записи,
                                       # сверяет формулы и сводку, затем всё удаляет
npx tsx scripts/check-rollups.mts      # пересчитывает все rollup-поля из дочерних записей и сравнивает
npx tsx scripts/check-rollups.mts --fix
```

`check-rollups` нужен из-за особенности Tablox: при удалении связанной записи итоги родителя не
пересчитываются. Приложение поэтому сначала отвязывает запись, а потом удаляет её.

## Чистый стенд

Тот же код можно направить на копию базы: при другом `TEABLE_BASE_ID` id таблиц определяются по их названиям,
а запись идёт по именам полей. Так работает чистый стенд для клиента — копия базы без партий, движений, платежей и
остатков (справочники товаров, счетов, контрагентов и настройки сохранены, начальные остатки обнулены):
Vercel-проект `kuritsa-stend` (https://kuritsa-stend.vercel.app), база «Курица — чистый стенд».
